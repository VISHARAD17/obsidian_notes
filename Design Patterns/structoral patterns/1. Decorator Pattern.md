> Decorator pattern is a structural pattern that lets you dynamically add new behaviour or responsibilities to objects without modifying their underlying code.

##### **Used when**:
- when we want to extend the functionality of a class without using a subclass.
- define or compose behaviours at runtime
- to avoid bloated classes with if-else logic for optional features

**Example**: Adding feature to a text renderer, we can use decorator pattern to add, like support for bold or italic text, etc.

> Its takes a  already existing implementation and wraps it using a decorator class to create new versions of existing class. i.e. using decorator class to create boldviewclass from plainviewclass.

#### **Implementation**
Create a base component
```java
public interface TextView {
	void render();
}
```
First concrete implementation
```java
public class PlainTextView implements TextView {
	private final String text;
	public PlainTextView(String text){
		this.text = text;
	}
	@override
	public void render(){
		System.out.print(text);
	}
}
```
Now create **Decorator class** (here use the same interface so that this new class can be use to replace the old one ie. PlainView.
```java
public abstract class TextDecorator implements TextView {
	protected final TextView inner;
	public TextDecorator(TextView inner){
		this.inner = inner;
	}
}
```
Now, using this kind of decorator class we can create new flavours of this class like `BoldDecorator` , `ItalicDecorator`, etc, by overriding its `TextDecorator` method
