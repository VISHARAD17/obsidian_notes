### 56. Binary Search — #704
**Difficulty:** Easy

**Pattern & Key Insight:**
- **while(left <= right), overflow-safe mid** — `mid = left + (right - left) / 2`. The `<=` means we check every element; `left = mid + 1` / `right = mid - 1` avoids infinite loops.

`````col
````col-md
**Explanation:**
1. `left = 0`, `right = n-1`
2. While `left <= right`:
   - Compute `mid`
   - If `nums[mid] == target` → return mid
   - If `nums[mid] < target` → `left = mid + 1`
   - Else → `right = mid - 1`
3. Return -1
````

````col-md
**Code:**
```java
public int search(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return mid;
        else if (nums[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return -1;
}
```
````
`````

**Complexity:** Time: O(log n) | Space: O(1)

**Edge Cases:**
- Single element → one comparison
- Target not in array → returns -1
- Target at first/last position

### 57. Search Insert Position — #35
**Difficulty:** Easy

**Pattern & Key Insight:**
- **Binary search — leftmost insertion point** — when loop ends, `left` is always the correct insertion position (first index where `nums[i] >= target`).

`````col
````col-md
**Explanation:**
1. Standard binary search
2. If found → return mid
3. If not found → `left` is the insertion point
4. Works because left converges to first element ≥ target
````

````col-md
**Code:**
```java
public int searchInsert(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return mid;
        else if (nums[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return left;
}
```
````
`````

**Complexity:** Time: O(log n) | Space: O(1)

**Edge Cases:**
- Target smaller than all → returns 0
- Target larger than all → returns n
- Target already exists → returns its index

### 58. First Bad Version — #278
**Difficulty:** Easy

**Pattern & Key Insight:**
- **Binary search — find first true in boolean sequence** — the sequence is `[false, false, ..., true, true, ...]`. Find the boundary where it flips.

`````col
````col-md
**Explanation:**
1. `left = 1`, `right = n`
2. If `isBadVersion(mid)` → bad version is at mid or earlier → `right = mid`
3. Else → bad version is after mid → `left = mid + 1`
4. Loop ends when `left == right` → answer
````

````col-md
**Code:**
```java
public int firstBadVersion(int n) {
    int left = 1, right = n;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (isBadVersion(mid)) right = mid;
        else left = mid + 1;
    }
    return left;
}
```
````
`````

**Complexity:** Time: O(log n) | Space: O(1)

**Edge Cases:**
- First version is bad → returns 1
- Last version is bad → converges to n

### 59. Search a 2D Matrix — #74
**Difficulty:** Medium

**Pattern & Key Insight:**
- **Binary search on flattened 2D index** — treat the matrix as a 1D sorted array. Map `mid` to `(mid / cols, mid % cols)`.

`````col
````col-md
**Explanation:**
1. `left = 0`, `right = rows*cols - 1`
2. Compute mid, convert to 2D: `row = mid / cols`, `col = mid % cols`
3. Standard binary search comparison
4. Return true/false
````

````col-md
**Code:**
```java
public boolean searchMatrix(int[][] matrix, int target) {
    int rows = matrix.length, cols = matrix[0].length;
    int left = 0, right = rows * cols - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        int val = matrix[mid / cols][mid % cols];
        if (val == target) return true;
        else if (val < target) left = mid + 1;
        else right = mid - 1;
    }
    return false;
}
```
````
`````

**Complexity:** Time: O(log(m×n)) | Space: O(1)

**Edge Cases:**
- 1×1 matrix → single comparison
- Target smaller than first element → false
- Target larger than last element → false

### 60. Sqrt(x) — #69
**Difficulty:** Easy

**Pattern & Key Insight:**
- **Binary search on integer answer range** — find largest `k` such that `k * k <= x`. Search on the answer space [0, x].

`````col
````col-md
**Explanation:**
1. `left = 0`, `right = x`
2. Compute `mid`, check `mid * mid` vs x
3. If `mid * mid <= x` → answer is mid or higher → `left = mid + 1`
4. Else → too big → `right = mid - 1`
5. Return `right` (last valid)
````

````col-md
**Code:**
```java
public int mySqrt(int x) {
    int left = 0, right = x;
    while (left <= right) {
        long mid = left + (right - left) / 2;
        if (mid * mid <= x) left = (int) mid + 1;
        else right = (int) mid - 1;
    }
    return right;
}
```
````
`````

**Complexity:** Time: O(log x) | Space: O(1)

**Edge Cases:**
- x = 0 → returns 0
- x = 1 → returns 1
- Use `long` for mid*mid to avoid overflow

### 61. Median of Two Sorted Arrays — #4
**Difficulty:** Hard

**Pattern & Key Insight:**
- **Binary search on partition point of smaller array** — partition both arrays such that left half has `(m+n+1)/2` elements. Binary search on the smaller array's partition.

`````col
````col-md
**Explanation:**
1. Ensure `nums1` is the smaller array
2. Binary search on partition `i` in nums1 (0 to m)
3. Derive `j = (m+n+1)/2 - i` for nums2
4. Check: `maxLeft1 <= minRight2` AND `maxLeft2 <= minRight1`
5. If valid → median from max of lefts and min of rights
````

````col-md
**Code:**
```java
public double findMedianSortedArrays(int[] nums1, int[] nums2) {
    if (nums1.length > nums2.length) return findMedianSortedArrays(nums2, nums1);
    int m = nums1.length, n = nums2.length;
    int left = 0, right = m;
    while (left <= right) {
        int i = (left + right) / 2;
        int j = (m + n + 1) / 2 - i;
        int maxL1 = i == 0 ? Integer.MIN_VALUE : nums1[i - 1];
        int minR1 = i == m ? Integer.MAX_VALUE : nums1[i];
        int maxL2 = j == 0 ? Integer.MIN_VALUE : nums2[j - 1];
        int minR2 = j == n ? Integer.MAX_VALUE : nums2[j];
        if (maxL1 <= minR2 && maxL2 <= minR1) {
            if ((m + n) % 2 == 0)
                return (Math.max(maxL1, maxL2) + Math.min(minR1, minR2)) / 2.0;
            else return Math.max(maxL1, maxL2);
        } else if (maxL1 > minR2) right = i - 1;
        else left = i + 1;
    }
    return 0;
}
```
````
`````

**Complexity:** Time: O(log(min(m,n))) | Space: O(1)

**Edge Cases:**
- One array empty → median of the other
- Arrays of vastly different sizes
- Even vs odd total length → average vs single value

### 62. Find Minimum in Rotated Sorted Array — #153
**Difficulty:** Medium

**Pattern & Key Insight:**
- **BS on condition — find inflection point** — compare `nums[mid]` with `nums[right]`. If `mid > right`, minimum is in right half. No target needed.

`````col
````col-md
**Explanation:**
1. `left = 0`, `right = n-1`
2. While `left < right`:
   - If `nums[mid] > nums[right]` → min is in `[mid+1, right]`
   - Else → min is in `[left, mid]`
3. Return `nums[left]`
````

````col-md
**Code:**
```java
public int findMin(int[] nums) {
    int left = 0, right = nums.length - 1;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] > nums[right]) left = mid + 1;
        else right = mid;
    }
    return nums[left];
}
```
````
`````

**Complexity:** Time: O(log n) | Space: O(1)

**Edge Cases:**
- Not rotated (sorted) → first element
- Rotated by 1 → last element is min

### 63. Search in Rotated Sorted Array — #33
**Difficulty:** Medium

**Pattern & Key Insight:**
- **BS — identify sorted half, check if target is in it** — one half is always sorted. Check if target lies in the sorted half; if yes, go there; else go opposite.

`````col
````col-md
**Explanation:**
1. Standard BS: compute mid
2. If `nums[left] <= nums[mid]` → left half sorted:
   - If target in `[nums[left], nums[mid])` → `right = mid - 1`
   - Else → `left = mid + 1`
3. Else → right half sorted, apply same logic
````

````col-md
**Code:**
```java
public int search(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return mid;
        if (nums[left] <= nums[mid]) {
            if (target >= nums[left] && target < nums[mid]) right = mid - 1;
            else left = mid + 1;
        } else {
            if (target > nums[mid] && target <= nums[right]) left = mid + 1;
            else right = mid - 1;
        }
    }
    return -1;
}
```
````
`````

**Complexity:** Time: O(log n) | Space: O(1)

**Edge Cases:**
- Not rotated → standard binary search
- Target at rotation point
- Single element array

### 64. Search in Rotated Sorted Array II — #81
**Difficulty:** Medium

**Pattern & Key Insight:**
- **Rotated BS with duplicates — handle `nums[left] == nums[mid]`** — when values at left and mid are equal, we can't determine which half is sorted. Fix: `left++` to skip.

`````col
````col-md
**Explanation:**
1. Same as #33, but add: if `nums[left] == nums[mid]` → `left++` (skip ambiguity)
2. This degrades worst case to O(n) but handles duplicates
3. Rest is identical to #33 logic
````

````col-md
**Code:**
```java
public boolean search(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return true;
        if (nums[left] == nums[mid]) { left++; continue; }
        if (nums[left] <= nums[mid]) {
            if (target >= nums[left] && target < nums[mid]) right = mid - 1;
            else left = mid + 1;
        } else {
            if (target > nums[mid] && target <= nums[right]) left = mid + 1;
            else right = mid - 1;
        }
    }
    return false;
}
```
````
`````

**Complexity:** Time: O(log n) average, O(n) worst | Space: O(1)

**Edge Cases:**
- All same elements → O(n) scan
- Duplicates at boundaries

**Difficulty:** Medium

**Pattern & Key Insight:**
- **BS on local property (move toward the rising slope)** — if `nums[mid] < nums[mid+1]`, peak is to the right. Else peak is at mid or to the left.

`````col
````col-md
**Explanation:**
1. `left = 0`, `right = n-1`
2. While `left < right`:
   - If `nums[mid] < nums[mid+1]` → rising, peak is right → `left = mid + 1`

````

public int findPeakElement(int[] nums) {
    int left = 0, right = nums.length - 1;

        else right = mid;
    }
    return left;
}
```
````
`````

### 66. Koko Eating Bananas — #875
**Difficulty:** Medium

**Pattern & Key Insight:**
- **BS on answer — find minimum k satisfying condition** — binary search on eating speed `k`. For each `k`, check if Koko can finish within `h` hours. Monotonic: higher k → fewer hours.

`````col
````col-md
**Explanation:**
1. Search space: `[1, max(piles)]`
2. For each `mid` (speed), compute hours needed: `sum(ceil(pile/mid))`
3. If hours <= h → speed might work, try smaller → `right = mid`
4. Else → need faster → `left = mid + 1`
````

````col-md
**Code:**
```java
public int minEatingSpeed(int[] piles, int h) {
    int left = 1, right = Arrays.stream(piles).max().getAsInt();
    while (left < right) {
        int mid = left + (right - left) / 2;
        int hours = 0;
        for (int p : piles) hours += (p + mid - 1) / mid;
        if (hours <= h) right = mid;
        else left = mid + 1;
    }
    return left;
}
```
````
`````

**Complexity:** Time: O(n × log(max)) | Space: O(1)

**Edge Cases:**
- h == piles.length → speed = max pile
- Single pile → speed = ceil(pile / h)

### 67. Capacity to Ship Packages Within D Days — #1011
**Difficulty:** Medium

**Pattern & Key Insight:**
- **BS on answer — minimum capacity** — binary search on ship capacity. Feasibility check: greedily assign packages to days, count days needed.

`````col
````col-md
**Explanation:**
1. Search space: `[max(weights), sum(weights)]`
2. For each capacity `mid`, simulate shipping:
   - Add weights greedily until exceeds `mid`, then new day
3. If days <= d → try smaller capacity → `right = mid`
4. Else → need more capacity → `left = mid + 1`
````

````col-md
**Code:**
```java
public int shipWithinDays(int[] weights, int days) {
    int left = 0, right = 0;
    for (int w : weights) { left = Math.max(left, w); right += w; }
    while (left < right) {
        int mid = left + (right - left) / 2;
        int d = 1, load = 0;
        for (int w : weights) {
            if (load + w > mid) { d++; load = 0; }
            load += w;
        }
        if (d <= days) right = mid;
        else left = mid + 1;
    }
    return left;
}
```
````
`````

**Complexity:** Time: O(n × log(sum)) | Space: O(1)

**Edge Cases:**
- days == 1 → capacity must be sum of all weights
- days == n → capacity = max single weight

### 68. Time Based Key-Value Store — #981
**Difficulty:** Medium

**Pattern & Key Insight:**
- **HashMap + BS on timestamps (floor value)** — store (timestamp, value) pairs per key. Binary search for the largest timestamp ≤ query timestamp.

`````col
````col-md
**Explanation:**
1. HashMap<String, List<Pair<timestamp, value>>>
2. `set`: append to key's list (timestamps are increasing)
3. `get`: binary search for largest timestamp ≤ query
4. Return corresponding value (or "" if none)
````

````col-md
**Code:**
```java
class TimeMap {
    Map<String, List<int[]>> map = new HashMap<>();

    public void set(String key, String value, int timestamp) {
        map.computeIfAbsent(key, k -> new ArrayList<>())
           .add(new int[]{timestamp, value.hashCode()});
    }
    // Simplified — actual stores String values:
}

// Full version with TreeMap:
class TimeMap {
    Map<String, TreeMap<Integer, String>> map = new HashMap<>();

    public void set(String key, String value, int timestamp) {
        map.computeIfAbsent(key, k -> new TreeMap<>()).put(timestamp, value);
    }

    public String get(String key, int timestamp) {
        if (!map.containsKey(key)) return "";
        var entry = map.get(key).floorEntry(timestamp);
        return entry == null ? "" : entry.getValue();
    }
}
```
````
`````

**Complexity:** Time: O(log n) per get, O(1) per set | Space: O(n)

**Edge Cases:**
- Query timestamp before any set → ""
- Multiple sets at same key with different timestamps
- Query with exact timestamp match

### 69. Split Array Largest Sum — #410
**Difficulty:** Hard

**Pattern & Key Insight:**
- **BS on answer — minimize the maximum subarray sum** — binary search on the max sum allowed. Greedy check: can we split into ≤ k subarrays with each sum ≤ mid?

`````col
````col-md
**Explanation:**
1. Search space: `[max(nums), sum(nums)]`
2. For each `mid` (max allowed sum per subarray):
   - Greedily assign elements to subarrays
   - When adding next element exceeds `mid`, start new subarray
3. If subarrays needed <= k → try smaller → `right = mid`
4. Else → need larger limit → `left = mid + 1`
````

````col-md
**Code:**
```java
public int splitArray(int[] nums, int k) {
    int left = 0, right = 0;
    for (int n : nums) { left = Math.max(left, n); right += n; }
    while (left < right) {
        int mid = left + (right - left) / 2;
        int splits = 1, sum = 0;
        for (int n : nums) {
            if (sum + n > mid) { splits++; sum = 0; }
            sum += n;
        }
        if (splits <= k) right = mid;
        else left = mid + 1;
    }
    return left;
}
```
````
`````

**Complexity:** Time: O(n × log(sum)) | Space: O(1)

**Edge Cases:**
- k == 1 → answer is sum of all elements
- k == n → answer is max single element
- All elements equal → evenly divided
