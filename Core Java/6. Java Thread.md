### 1. **Introduction to Multi-Threading**
   - **Single-Tasking**: In older systems with one CPU, tasks were executed sequentially, one at a time.
   - **Multi-Tasking**: Modern CPUs switch between tasks rapidly, giving the illusion of parallelism, though only one task runs at a time per CPU.
   - **Multi-Threading**: Within a single application, developers create multiple threads. With one CPU, threads are switched; with multiple CPUs, threads can run in parallel.
     - **Example**: Thread 1 downloads data, Thread 2 connects to a database, and Thread 3 performs another task, leveraging multiple CPUs for faster execution.
   - **Benefits**: Improved CPU utilization, faster response times (e.g., millisecond responses despite handling large datasets).
   - **Challenges**: Shared memory can cause issues like deadlocks, race conditions, and data inconsistencies, requiring careful synchronization.

### 2. **Creating Threads in Java**
   - **Using `Thread` Class (Legacy)**:
     - Extend `Thread` and override the `run` method.
     - Example:
       ```java
       class MyThread extends Thread {
           public void run() {
               System.out.println("Thread 1 is running");
           }
       }
       MyThread t1 = new MyThread();
       t1.start();
       ```
     - Not recommended due to lack of flexibility.
   - **Using Lambda Expressions**:
     - More modern approach for cleaner code.
     - Example:
       ```java
       Thread t2 = new Thread(() -> System.out.println("Thread 2 is running"));
       t2.start();
       ```
   - **Using `Runnable` Interface (Recommended)**:
     - Implement `Runnable` and pass it to a `Thread` object.
     - Example:
       ```java
       Runnable runnable = () -> {
           System.out.println("Thread 3 is running");
           try {
               Thread.sleep(2000);
           } catch (InterruptedException e) {
               e.printStackTrace();
           }
           System.out.println("Thread 3 completed");
       };
       Thread t3 = new Thread(runnable, "RunnableThread");
       t3.start();
       ```
     - `Runnable` is a functional interface with a single `run` method, making it ideal for lambda expressions.
   - **Thread States**:
     - **New**: Thread instantiated but not started.
     - **Runnable**: After `start()`, waiting for CPU allocation.
     - **Running**: Actively executing.
     - **Blocked/Waiting**: Waiting for a resource (e.g., I/O, lock).
     - **Timed Waiting**: Paused for a specific time (e.g., `sleep`, `join`).
     - **Terminated**: Completed execution.
     - **Example**: In a chat application, a thread for a user moves from `New` (user opens app) to `Runnable` (user logs in), `Running` (sends message), `Blocked` (waits for network), and `Terminated` (user logs out).

### 3. **Daemon Threads**
   - **Definition**: Background threads that don’t prevent JVM exit when non-daemon threads finish.
   - **Use Cases**: Logging, monitoring, garbage collection.
   - **Example**:
     ```java
     Thread t3 = new Thread(runnable);
     t3.setDaemon(true); // Set as daemon
     t3.start();
     System.out.println("Main thread ended");
     ```
     - The main thread exits without waiting for the daemon thread to complete.
   - **Interview Relevance**: Explain daemon threads and show how the main thread doesn’t wait for them.

### 4. **Java Memory Model (JMM)**
   - **Structure**:
     - **Heap**: Stores shared objects accessible by all threads.
     - **Thread Stack**: Stores local variables unique to each thread.
     - **Example**: A shared object in the heap is referenced by multiple threads, but local variables like `int x = 0` are thread-specific.
   - **Issues with Shared Objects**:
     - **Visibility Problem**: One thread updates a shared variable, but another thread sees the old value due to CPU caching.
     - **Race Condition**: Multiple threads modify a shared variable, leading to inconsistent results.
   - **CPU Architecture**:
     - Each CPU has registers and a cache, fetching data from main memory. Updates may stay in the cache, causing visibility issues.
     - Example: Thread 1 updates a variable in CPU 1’s cache, but Thread 2 on CPU 2 reads the old value from main memory.

### 5. **Handling Synchronization Issues**
   - **Volatile Keyword**:
     - Ensures visibility by forcing threads to read/write directly to main memory, bypassing cache.
     - **Example**:
       ```java
       class Shared {
           volatile boolean flag = false;
           public void setFlag() { flag = true; }
           public boolean getFlag() { return flag; }
       }
       Shared shared = new Shared();
       new Thread(() -> { shared.setFlag(); }).start();
       new Thread(() -> { while (!shared.getFlag()) {} System.out.println("Flag is true"); }).start();
       ```
       - Without `volatile`, Thread 2 may not see the updated `flag` value, causing an infinite loop.
   - **Synchronized Keyword**:
     - Provides mutual exclusion (mutex) via locks, ensuring only one thread accesses a critical section.
     - Can be applied to methods, static methods, or code blocks.
     - **Example**:
       ```java
       class Counter {
           int count = 0;
           synchronized void increment() { count++; }
       }
       ```
       - Prevents race conditions by locking the `increment` method.
   - **Atomic Classes**:
     - Non-lock-based, leveraging hardware support (e.g., Compare-and-Swap) for atomic operations.
     - **Example**:
       ```java
       import java.util.concurrent.atomic.AtomicInteger;
       class Counter {
           AtomicInteger count = new AtomicInteger(0);
           void increment() { count.incrementAndGet(); }
       }
       ```
       - Ensures atomic increment, avoiding race conditions.
   - **Comparison**:

| Feature              | Synchronized                   | Volatile              | Atomic Classes             |
| -------------------- | ------------------------------ | --------------------- | -------------------------- |
| **Mutual Exclusion** | Yes (lock-based)               | No                    | No                         |
| **Visibility**       | Yes                            | Yes                   | Yes                        |
| **Atomicity**        | Yes                            | No                    | Yes (single op only)       |
| **Performance**      | Slower (locking overhead)      | Faster                | Fast (hardware support)    |
| **Use Case**         | Compound actions needing mutex | Read/write visibility | Atomic increment/decrement |
 - **Example Scenario**:
   - Use `synchronized` for critical sections requiring exclusive access.
   - Use `volatile` when one thread updates a flag and others read it.
   - Use `AtomicInteger` for thread-safe counters.

### 6. **Thread Local**
   - **Purpose**: Stores thread-specific variables, avoiding synchronization issues.
   - **Use Cases**: User sessions, database connections, thread context.
   - **Example**:
     ```java
     ThreadLocal<Long> userId = new ThreadLocal<>();
     Runnable r1 = () -> {
         userId.set(1001L);
         System.out.println("User ID: " + userId.get());
         userId.remove(); // Prevent memory leaks
         System.out.println("After remove: " + userId.get()); // Null
     };
     new Thread(r1).start();
     ```
     - Each thread has its own copy of `userId`, inaccessible to others.
   - **InheritableThreadLocal**: Allows child threads to inherit parent thread’s values.
     - **Example**:
       ```java
       InheritableThreadLocal<String> data = new InheritableThreadLocal<>();
       data.set("Instagram");
       new Thread(() -> System.out.println("Child: " + data.get())).start(); // Prints "Instagram"
       ```
   - **Caution**: Remove `ThreadLocal` values after use to avoid memory leaks.

### 7. **Executor Service and Thread Pools**
   - **Purpose**: Manages a pool of threads, reducing thread creation overhead.
   - **Types**:
     - **Single Thread Executor**: One thread, sequential task execution.
       - **Example**:
         ```java
         ExecutorService executor = Executors.newSingleThreadExecutor();
         for (int i = 1; i <= 5; i++) {
             int taskId = i;
             executor.execute(() -> System.out.println("Task " + taskId));
         }
         executor.shutdown();
         ```
         - Tasks execute sequentially: Task 1, Task 2, ..., Task 5.
     - **Fixed Thread Pool**: Fixed number of threads (e.g., 3). Tasks wait in a queue if all threads are busy.
       - **Example**: With 3 threads and 5 tasks, the first 3 tasks run immediately, and the remaining 2 wait.
     - **Cached Thread Pool**: Dynamically adjusts thread count based on workload, terminating idle threads.
     - **Scheduled Thread Pool**: Executes tasks after a delay or at fixed intervals.
       - **Example**:
         ```java
         ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(2);
         scheduler.schedule(() -> System.out.println("Scheduled task"), 1, TimeUnit.SECONDS);
         ```
   - **ThreadPoolExecutor**:
     - Customizable with parameters: core pool size, max pool size, keep-alive time, blocking queue.
     - **Example**:
       ```java
       ThreadPoolExecutor executor = new ThreadPoolExecutor(1, 5, 0, TimeUnit.MILLISECONDS, new LinkedBlockingQueue<>(2));
       for (int i = 1; i <= 5; i++) {
           executor.execute(() -> System.out.println("Task"));
       }
       ```
       - Core size 1, max size 5, queue capacity 2. New threads start only when the queue is full.

### 8. **Producer-Consumer Problem**
   - **Definition**: Producers generate data, and consumers process it, using a shared queue.
   - **Challenges**:
     - Producer faster than consumer: Queue overflow.
     - Consumer faster than producer: Attempts to consume from an empty queue.
   - **Solution with BlockingQueue**:
     - Automatically handles synchronization using `put` (waits if queue full) and `take` (waits if queue empty).
     - **Example**:
       ```java
       BlockingQueue<Integer> queue = new ArrayBlockingQueue<>(5);
       new Thread(() -> { for (int i = 0; i < 10; i++) queue.put(i); }).start(); // Producer
       new Thread(() -> { while (true) System.out.println(queue.take()); }).start(); // Consumer
       ```
   - **Alternative**: Use `synchronized`, `wait`, and `notifyAll` with a regular list, but this is error-prone and complex.

### 9. **Virtual Threads (Java 21)**
   - **Purpose**: Lightweight threads for high concurrency, not speed.
   - **Use Cases**: Tasks involving waiting (e.g., database, API calls), not CPU-intensive operations.
   - **Example**:
     ```java
     for (int i = 0; i < 1_000_000; i++) {
         Thread.ofVirtual().start(() -> System.out.println("Virtual thread"));
     }
     ```
     - Successfully creates millions of virtual threads, unlike platform threads, which fail around 9,000 due to memory limits.
   - **Key Points**:
     - Virtual threads are daemon by default, managed by JVM, not OS.
     - Ideal for scalability, not performance.

### 10. **Common Interview Questions**
   - **Process vs. Thread**: Process is an independent program with its own memory; threads share memory within a process.
   - **Daemon Thread**: Background thread, doesn’t block JVM exit.
   - **Deadlock**:
     - Two threads wait indefinitely for each other’s resources.
     - **Example**: Thread A locks Resource 1 and waits for Resource 2; Thread B locks Resource 2 and waits for Resource 1.
     - **Prevention**: Acquire locks in a fixed order, use timeouts, or detect with tools like ThreadMXBean.
   - **Livelock**:
     - Threads change states but make no progress (e.g., two people stepping aside in a narrow hallway).
     - **Prevention**: Introduce random delays or fallback mechanisms.
   - **Starvation**:
     - A thread is denied resources due to higher-priority threads.
     - **Prevention**: Use fair scheduling or reentrant locks.
   - **Fork-Join Framework**:
     - Parallelizes divide-and-conquer algorithms by splitting tasks into subtasks, executing them in parallel, and merging results.
     - **Example**: Summing an array by splitting it into smaller ranges.
     - **Caution**: Avoid for simple tasks due to overhead.

### Additional Notes
- **Happens-Before**: Ensures instructions are not reordered in a way that breaks multi-threaded logic, enforced by `volatile`, `synchronized`, etc.
- **Runnable vs. Callable**: `Runnable` has a `void run()` method; `Callable` returns a result and can throw exceptions.
