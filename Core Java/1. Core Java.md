#java
#### 1. **What is Java, and why is it not a pure object-oriented programming language?**
- **Definition**: Java is a class-based, object-oriented programming language known for simplicity, portability, and its "write once, run anywhere" feature, enabled by compiling code into platform-independent byte code.
- **Why not purely object-oriented?**
  - Java uses **primitive data types** (e.g., `int`, `char`, `float`) that are not objects, unlike pure object-oriented languages like Smalltalk, where everything is an object.
  - The **static keyword** allows methods and variables to be accessed without creating an object, violating the principle that all operations should be performed through objects.
- **Example**: 
  - Primitive: `int x = 5;` (not an object).
  - Static: `public static void main(String[] args)` can be called without instantiating a class.
- **Additional Info**: Java provides **wrapper classes** (e.g., `Integer` for `int`) to treat primitives as objects when needed, but direct primitive operations make it impurely object-oriented.

#### 2. **Key Components of Running a Java Program**
- **Compilation and Execution Process**:
  - **Java Source File** (e.g., `Example.java`) is compiled by the **Java Compiler** (part of JDK) into **bytecode** (`Example.class`), which is platform-independent.
  - The **JVM (Java Virtual Machine)** interprets and executes the byte code, ensuring it runs consistently across platforms.
- **Key Components**:
  - **JDK (Java Development Kit)**: Includes tools like the Java compiler (`javac`) for creating Java applications.
  - **JRE (Java Runtime Environment)**: Provides the JVM and libraries to run Java programs.
  - **JVM**: Executes byte code by loading it into memory and linking with system libraries.
- **Example**: Writing `Example.java`, compiling it to `Example.class`, and running it via JVM on any platform.
- **Additional Info**: The JVM’s platform independence is achieved through its ability to translate byte code into machine-specific instructions.

#### 3. **Main Features of Java**
- **Key Features**:
  - **Simple**: Easy-to-learn syntax, avoids complex concepts like pointers.
  - **Secure**: Built-in security features (e.g., sandboxing) prevent unauthorized access.
  - **Portable**: Runs on any platform with a JVM.
  - **Object-Oriented**: Organizes code through objects for modularity.
  - **Multithreaded**: Supports concurrent task execution.
  - **Robust**: Strong memory management and error handling.
  - **Interoperable**: Can interact with languages like C/C++.
- **Example**: A Java web application can run on Windows, Linux, or macOS without modification due to JVM.
- **Additional Info**: Java’s byteCode compilation makes it slower than C++ but efficient enough for enterprise applications due to its near-machine-code nature.

#### 4. **What is the Java String Pool?**
- **Definition**: A memory area in the heap where string literals are stored to optimize memory usage by reusing identical strings.
- **How it Works**: When a string literal (e.g., `"ABC"`) is created, Java checks the string pool. If it exists, the reference is reused; otherwise, a new string is added.
- **Example**: 
  ```java
  String s1 = "ABC";
  String s2 = "ABC"; // s1 and s2 point to the same memory location in the string pool
  String s3 = new String("ABC"); // Creates a new object in the heap, not the string pool
  ```
- **Additional Info**: Using the `new` keyword bypasses the string pool, creating a new object, which is less memory-efficient.

#### 5. **What are Wrapper Classes and Why Are They Needed?**
- **Definition**: Wrapper classes (e.g., `Integer`, `Float`, `Character`) convert primitive types into objects, providing additional functionality.
- **Why Needed**:
  - Enable primitives to be used in object-oriented contexts (e.g., collections like `ArrayList` that only store objects).
  - Provide methods like `Integer.parseInt()` or `Integer.toString()`.
  - Support **autoboxing** (automatic conversion of primitive to object, e.g., `int` to `Integer`) and **unboxing** (object to primitive).
- **Example**:
  ```java
  ArrayList<Integer> list = new ArrayList<>();
  list.add(5); // Autoboxing: int 5 is converted to Integer
  int num = list.get(0); // Unboxing: Integer to int
  ```
- **Additional Info**: Wrapper classes are essential for frameworks like Java Collections, which don’t support primitives directly.

#### 6. **How Does Java’s Collection Framework Help Manage Data in an Online Bookstore?**
- **Scenario**: Managing a bookstore with a list of books, unique genres, and author-to-book mappings.
- **Collections Used**:
  - **ArrayList**: For a dynamic list of all books (e.g., catalog).
  - **HashSet**: For unique genres, preventing duplicates.
  - **HashMap**: For mapping authors (keys) to their books (values, e.g., a list of books).
- **Example**:
  ```java
  ArrayList<String> bookCatalog = new ArrayList<>();
  bookCatalog.add("Book1"); // Dynamic, grows as needed
  HashSet<String> genres = new HashSet<>();
  genres.add("Fiction"); // Ensures no duplicate genres
  HashMap<String, List<String>> authorBooks = new HashMap<>();
  authorBooks.put("Author1", Arrays.asList("Book1", "Book2")); // Maps author to books
  ```
- **Why Important**: Collections provide efficient methods for adding, removing, and searching data, reducing the need for custom data structures and improving code maintainability.
- **Additional Info**: The Collections Framework is optimized for performance, with `HashSet` offering O(1) lookup and `ArrayList` providing dynamic resizing.

#### 7. **Use of `this` and `super` Keywords**
- **`this`**: Refers to the current object or class, used to distinguish instance variables from parameters or access current object methods.
  - **Example**:
    ```java
    class Person {
        String name;
        Person(String name) {
            this.name = name; // Differentiates instance variable from parameter
        }
        void display() {
            System.out.println(this.name); // Refers to current object's name
        }
    }
    ```
- **`super`**: Refers to the parent class, used to call parent class methods, constructors, or access parent class fields. It has to be first in the method. Also, `this` also needed to be first in the method if called. Hence both cannot be in the same method.
  - **Example**:
    ```java
    class Animal {
        void makeSound() {
            System.out.println("Animal sound");
        }
    }
    class Dog extends Animal {
        void makeSound() {
            super.makeSound(); // Calls parent class method
            System.out.println("Bark");
        }
    }
    ```
- **Additional Info**: These keywords enhance code clarity in inheritance and constructor scenarios, preventing ambiguity.

#### 8. **Static vs. Instance Methods**
- **Static Methods**:
  - Belong to the class, not an object.
  - Called using the class name (e.g., `ClassName.method()`).
  - Can only access static variables/methods, cannot use `this`.
- **Instance Methods**:
  - Belong to an object, require an instance to be called (e.g., `obj.method()`).
  - Can access both static and instance variables/methods, use `this` to refer to the current object.
- **Example**:
  ```java
  class Example {
      static void staticMethod() {
          System.out.println("Static method");
      }
      void instanceMethod() {
          System.out.println("Instance method");
      }
  }
  public class Main {
      public static void main(String[] args) {
          Example.staticMethod(); // No object needed
          Example obj = new Example();
          obj.instanceMethod(); // Requires object
      }
  }
  ```
- **Additional Info**: Static methods are used for utility functions (e.g., `Math.sqrt()`), while instance methods handle object-specific behavior, cause static methods or variables does not depend on class state.

#### 9. **Constructors and Their Types**
- **Definition**: Special methods used to initialize objects, with the same name as the class and no return type.
- **Types**:
  - **Default Constructor**: No arguments, automatically provided if no constructor is defined.
    - **Example**:
      ```java
      class Bike {
          Bike() {
              System.out.println("Bike is created");
          }
      }
      ```
  - **Parameterized Constructor**: Takes arguments to initialize object fields.
    - **Example**:
      ```java
      class Car {
          String model;
          int year;
          Car(String m, int y) {
              model = m;
              year = y;
          }
          void display() {
              System.out.println("Model: " + model + ", Year: " + year);
          }
      }
      ```
- **Additional Info**: Constructors are called automatically with the `new` keyword and can be overloaded for flexibility.

#### 10. **StringBuffer vs. StringBuilder**
- **StringBuffer**:
  - Synchronized (thread-safe), ensuring only one thread can modify it at a time.
  - Slower due to synchronization overhead.
  - Suitable for multithreaded environments.
- **StringBuilder**:
  - Non-synchronized, faster as it lacks thread safety.
  - Ideal for single-threaded applications.
- **Example**:
  ```java
  StringBuffer sbf = new StringBuffer("Hello");
  sbf.append(" World"); // Thread-safe
  StringBuilder sbd = new StringBuilder("Hello");
  sbd.append(" World"); // Faster, not thread-safe
  ```
- **Additional Info**: Use `StringBuilder` for performance in single-threaded scenarios; `StringBuffer` for thread safety in concurrent applications.

#### 11. **Abstract Classes vs. Interfaces**
- **Abstract Classes**:
  - Can have both abstract (unimplemented) and non-abstract (implemented) methods.
  - Support single inheritance.
  - Can have various variable types (e.g., final, static).
- **Interfaces**:
  - Only abstract methods (until Java 8, which added default methods).
  - Support multiple inheritance.
  - Variables are `public static final` by default.
- **Example**:
  ```java
  abstract class Shape {
      abstract void draw();
      void move() { System.out.println("Moving"); }
  }
  interface Drawable {
      void draw();
  }
  class Circle extends Shape implements Drawable {
      public void draw() { System.out.println("Draw Circle"); }
  }
  ```
- **Additional Info**: Java 8 introduced default and static methods in interfaces, blurring the line with abstract classes, but interfaces remain more flexible for multiple inheritance.

#### 12. **Method Overloading and Overloading the Main Method**
- **Method Overloading**: Multiple methods with the same name but different parameters (number, type, or both).
  - **Example**:
    ```java
    class Overloading {
        void method(int x) { System.out.println("Int: " + x); }
        void method(double x) { System.out.println("Double: " + x); }
    }
    ```
- **Main Method Overloading**: Possible, but the JVM only calls `public static void main(String[] args)` as the entry point.
  - **Example**:
    ```java
    class MainOverload {
        public static void main(String[] args) {
            main(5); // Calls overloaded main
        }
        public static void main(int x) {
            System.out.println("Overloaded main: " + x);
        }
    }
    ```
- **Additional Info**: Overloading is an example of compile-time polymorphism, enhancing code flexibility.

#### 13. **Method Overriding and Restrictions**
- **Method Overriding**: A subclass provides a specific implementation for a method defined in its superclass, with the same method signature.
  - **Example**:
    ```java
    class Animal {
        void move() { System.out.println("Animal moves"); }
    }
    class Dog extends Animal {
        void move() { System.out.println("Dog runs"); }
    }
    ```
- **Restrictions**:
  - **Static Methods**: Cannot be overridden (they belong to the class, not objects).
  - **Private Methods**: Cannot be overridden (not visible to subclasses).
- **Additional Info**: Overriding enables runtime polymorphism, where the method called depends on the object’s actual type.

#### 14. **Exception Handling in Java**
- **Mechanism**: Handles runtime errors using `try`, `catch`, and `finally` blocks to ensure program continuity.
  - **Try**: Contains code that might throw an exception.
  - **Catch**: Handles specific exceptions.
  - **Finally**: Executes regardless of whether an exception occurs (e.g., for cleanup). But it will not be executed if any of the blocks above contains system.exit();
- **Example**:
  ```java
  try {
      int x = 10 / 0;
  } catch (ArithmeticException e) {
      System.out.println("Cannot divide by zero");
  } finally {
      System.out.println("Always executed");
  }
  ```
- **Additional Info**: Java’s exception hierarchy includes checked (e.g., `IOException`) and unchecked (e.g., `NullPointerException`) exceptions.

#### 15. **Thread Lifecycle in Java**
- **Stages**:
  - **New**: Thread created but not started.
  - **Runnable**: Thread is ready to run after `start()`.
  - **Running**: Thread is executing.
  - **Blocked/Waiting/Sleeping**: Thread is paused (e.g., waiting for I/O or sleep).
  - **Terminated**: Thread completes its task.
- **Example**: A thread created with `Thread t = new Thread();` moves to Runnable with `t.start()`.
- **Additional Info**: Understanding thread states is crucial for managing multitasking and synchronization in Java.

#### 16. **Singleton Class**
- **Definition**: Ensures only one instance of a class exists, controlling access to resources like database connections.
- **Implementation Steps**:
  - Private constructor to prevent instantiation.
  - Static method (`getInstance`) to provide global access.
  - Static instance variable to store the single instance.
- **Example**:
  ```java
  class Singleton {
      private static Singleton instance;
      private Singleton() {}
      public static Singleton getInstance() {
          if (instance == null) {
              instance = new Singleton();
          }
          return instance;
      }
  }
  ```
- **Additional Info**: Singleton is a creational design pattern, often used in logging or configuration management.

#### 17. **Aggregation vs. Composition**
- **Aggregation**: “Has-a” relationship where objects are independent (e.g., a department has students who can exist without it).
- **Composition**: Stronger “part-of” relationship where the child object depends on the parent (e.g., a library and its books; books are destroyed if the library is).
- **Example**:
  ```java
  class Department {
      List<Student> students; // Aggregation
  }
  class Library {
      List<Book> books; // Composition
  }
  ```
- **Additional Info**: Composition implies ownership and lifecycle dependency, while aggregation is looser.

#### 18. **Anonymous Inner Class**
- **Definition**: A nameless class defined and instantiated at once, used for one-time implementations of interfaces or classes.
- **Properties**: No name, no constructor, used for quick overrides.
- **Example**:
  ```java
  interface Age {
      void getAge();
  }
  class Main {
      public static void main(String[] args) {
          Age obj = new Age() {
              public void getAge() {
                  System.out.println("Age is 21");
              }

      }
  }
  ```
- **Additional Info**: Common in event handling (e.g., Java Swing) for concise code.

#### 19. **Implicit vs. Explicit Type Conversion**
- **Implicit (Automatic)**: Compiler converts smaller data types to larger ones (e.g., `int` to `double`).
  - **Example**: `int x = 5; double y = x; // y = 5.0`
- **Explicit (Manual)**: Programmer converts types using casting, risking data loss.
  - **Example**: `double x = 5.7; int y = (int) x; // y = 5`
- **Additional Info**: Explicit casting requires caution to avoid precision loss.

#### 20. **Volatile Keyword**
- **Purpose**: Ensures a variable’s value is always read from/written to main memory, not thread-local caches, for visibility across threads.
- **Example**:
  ```java
  volatile int counter = 0; // Changes visible to all threads immediately
  ```
- **Additional Info**: Lightweight alternative to synchronization, but doesn’t ensure atomicity (e.g., `counter++` still needs synchronization).

#### 22. **Access Specifiers**

#### 23. **Final, Finally, Finalize**

- **Additional Info**: `try-with-resources` is preferred over `finalize` in modern Java.

#### 23.5 Main Purpose of Default Methods in Java

**Default methods in Java interfaces were introduced to address the limitation that interfaces could only declare method signatures, not provide implementations.** The primary purposes are:

- **Backward Compatibility:** Default methods allow you to add new methods to interfaces without breaking existing implementations. Before default methods, adding a new method to an interface would require all implementing classes to provide an implementation, potentially breaking legacy code. With default methods, a default implementation is provided, so existing classes do not need to change 

- **Incremental Interface Evolution:** They enable library designers to evolve interfaces by adding new functionality over time, ensuring that older code remains compatible with newer versions of the interface
    
- **Avoiding Code Duplication:** Default methods can provide common functionality that can be shared across multiple implementing classes, reducing code duplication
    

**Example:**

``` java
public interface MyInterface {     
	void abc(); // Abstract method    
	default void defaultMethod() {        
		System.out.println("This is a default method.");    
	} 
}
```
In this example, implementing classes must define `abc()`, but `defaultMethod()` is automatically available and can be overridden if needed

| Purpose                | Benefit                                            |
| ---------------------- | -------------------------------------------------- |
| Backward Compatibility | Existing code doesn't break when interfaces evolve |
| Incremental Evolution  | New features can be added to interfaces easily     |
| Shared Functionality   | Common logic can be placed in the interface        |
#### 24. **Toggle Characters in a String**
- **Task**: Convert uppercase to lowercase and vice versa (e.g., "tHiS" → "ThIs").
- **Approach**: Iterate through characters, check case, and append toggled characters to a `StringBuilder`.
- **Example**:
  ```java
  String input = "tHiS";
  StringBuilder result = new StringBuilder();
  for (char c : input.toCharArray()) {
      if (Character.isUpperCase(c)) {
          result.append(Character.toLowerCase(c));
      } else {
          result.append(Character.toUpperCase(c));
      }
  }
  System.out.println(result); // Outputs: ThIs
  ```
- **Additional Info**: Using `StringBuilder` is efficient for string manipulation.

#### 25. **Count Digit Occurrences in a Number**
- **Task**: Count how many times a digit `D` appears in number `N` (e.g., `D=4`, `N=123446` → 2 occurrences).
- **Approach**: Extract digits using modulo, compare with `D`, and increment count.
- **Example**:
  ```java
  int countDigit(int n, int d) {
      int count = 0;
      while (n > 0) {
          if (n % 10 == d) count++;
          n /= 10;
      }
      return count;
  }
  ```
- **Additional Info**: Common interview question to test basic arithmetic operations.

#### 26. **Reverse Array Using Recursion**
- **Task**: Reverse an array (e.g., `[1, 10, 12, 13]` → `[13, 12, 10, 1]`) without extra space.
- **Approach**: Swap elements from start and end indices recursively.
- **Example**:
  ```java
  void reverseArray(int[] arr, int start, int end) {
      if (start >= end) return;
      int temp = arr[start];
      arr[start] = arr[end];
      arr[end] = temp;
      reverseArray(arr, start + 1, end - 1);
  }
  ```
- **Additional Info**: Recursion uses implicit stack space, but no extra array is needed.

#### 27. **Check if Strings are Anagrams**
- **Task**: Check if two strings have the same characters with the same frequency (e.g., "act" and "cat" are anagrams).
- **Approach**: Compare sorted character arrays of both strings.
- **Example**:
  ```java
  boolean isAnagram(String s1, String s2) {
      if (s1.length() != s2.length()) return false;
      char[] c1 = s1.toCharArray();
      char[] c2 = s2.toCharArray();
      Arrays.sort(c1);
      Arrays.sort(c2);
      return Arrays.equals(c1, c2);
  }
  ```
- **Additional Info**: Alternative approaches use frequency maps (e.g., `HashMap`) but sorting is simpler for interviews.

#### 28. **Find First and Last Occurrence of an Element in an Array**
- **Task**: Find indices of the first and last occurrence of a target in an array (e.g., `[1, 1, 2, 3, 1, 4, 5]`, target=1 → first=0, last=4).
- **Approach**: Iterate through the array, update first index on first match, and last index on every match.
- **Example**:
  ```java
  void findOccurrences(int[] arr, int target) {
      int first = -1, last = -1;
      for (int i = 0; i < arr.length; i++) {
          if (arr[i] == target) {
              if (first == -1) first = i;
              last = i;
          }
      }
      if (first == -1) System.out.println("Not found");
      else System.out.println("First: " + first + ", Last: " + last);
  }
  ```
- **Additional Info**: Linear time (O(n)) solution, commonly asked in coding interviews.

#### 30. **Deep Copy vs. Shallow Copy**
- **Deep Copy**: Creates a new object with independent copies of all fields; changes to one don’t affect the other.
  - **Example**:
    ```java
    class A {
        int x = 30;
    }
    A obj1 = new A();
    A obj2 = new A();
    obj2.x = 6;
    System.out.println(obj1.x); // Outputs: 30 (independent)
    ```
- **Shallow Copy**: Copies references, so both objects point to the same memory; changes affect both.
  - **Example**:
    ```java
    A obj1 = new A();
    A obj2 = obj1; // Shallow copy
    obj2.x = 6;
    System.out.println(obj1.x); // Outputs: 6 (same reference)
    ```
- **Additional Info**: Deep copy requires implementing `Cloneable` or custom copying logic for complex objects.

#### 31. List.of() vs Array.asList()
Here’s a concise summary of the differences between `List.of()` and `Arrays.asList()` in Java:

2. **Immutability**:
   - `List.of()`: Fully immutable (no modifications allowed).
   - `Arrays.asList()`: Partially mutable (can modify elements, not size).

3. **Input**:
   - `List.of()`: Takes individual elements or varargs.
   - `Arrays.asList()`: Requires an array.

4. **Null Handling**:
   - `List.of()`: Does not allow null elements (`NullPointerException`).
   - `Arrays.asList()`: Allows null elements.

5. **Backing**:
   - `List.of()`: Not backed by an array.
   - `Arrays.asList()`: Backed by the input array (changes affect both).

6. **Modifiable List**:
   - `List.of()`: Requires copying to `new ArrayList<>(List.of(...))`.
   - `Arrays.asList()`: Requires copying to `new ArrayList<>(Arrays.asList(...))`.

7. **Return Type**:
   - `List.of()`: Returns an internal immutable `List` implementation.
   - `Arrays.asList()`: Returns `Arrays.ArrayList` (a private class).

8. **Performance**:
   - `List.of()`: Optimized for immutability, memory-efficient.
   - `Arrays.asList()`: Lightweight, wraps existing array.

9. **Use Cases**:
   - `List.of()`: Ideal for immutable lists in modern Java.
   - `Arrays.asList()`: Useful for array-to-list conversion, element updates.

10. **Empty List**:
    - `List.of()`: Created with `List.of()`.
    - `Arrays.asList()`: Created with `Arrays.asList(new Object[0])`.
